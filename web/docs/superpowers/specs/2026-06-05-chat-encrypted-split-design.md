# 普通聊天与加密聊天拆分设计

## 目标
将当前统一的消息中心拆分为两条明确路径：
- `/chat`：默认普通聊天页面，承载好友/群聊的日常非加密会话，以及 AI 助手、我的收藏、加密通道入口。
- `/encrypted-chat`：独立加密聊天页面，只承载端到端加密好友/群聊会话，不包含 AI 助手和我的收藏。

## 已确认需求
1. 全部好友/群聊默认进入普通聊天。
2. 只有点击“加密通道”入口才进入独立加密聊天页。
3. 加密聊天页只显示已开启加密能力的对象，未开启的不显示。
4. 现有加密聊天历史直接沿用到新页面。
5. 加密聊天页的视觉风格要高级、专业、沉稳，带有克制的“黑客帝国”风格。

## 路由与页面职责
### `/chat`
- 保留为“消息中心”。
- 展示好友/群聊列表。
- 展示 AI 助手入口。
- 展示我的收藏入口。
- 新增加密通道入口，点击跳转 `/encrypted-chat`。
- 点击好友/群聊时进入普通聊天历史与发送流程。
- 移除当前加密状态主提示，不再把普通聊天页表达为加密页。

### `/encrypted-chat`
- 新增独立页面。
- 只保留聊天相关能力。
- 不显示 AI 助手入口。
- 不显示我的收藏入口。
- 左侧只展示可参与加密会话的好友与群聊。
- 沿用现有 E2EE 消息历史加载、加解密、发送、接收流程。

## 数据与消息链路
### 普通聊天链路
需要新增一套普通聊天消息链路，供 `/chat` 使用。

#### 好友普通聊天
- 新增普通好友消息模型、仓储、服务、处理器、路由。
- 普通聊天消息不依赖公钥，也不做加解密。
- 普通好友消息历史与发送接口独立于现有加密 `/messages` 语义。

#### 群普通聊天
- 新增普通群消息模型、仓储、服务、处理器、路由。
- 普通群消息按明文消息语义存储与返回。
- 普通群消息历史与发送接口独立于现有群加密消息链路。

### 加密聊天链路
`/encrypted-chat` 继续复用现有链路：
- 当前好友加密消息历史与发送接口。
- 当前群加密消息历史与发送接口。
- 当前端侧私钥、公钥、群消息 envelope 加解密逻辑。
- 当前 websocket 的加密消息消费逻辑。

## 会话筛选规则
### 普通页 `/chat`
- 好友列表：全部好友。
- 群聊列表：全部群聊。

### 加密页 `/encrypted-chat`
- 好友列表：只显示 `publicKey` 可用且算法匹配的好友。
- 群聊列表：只显示具备加密会话条件的群聊。
- 群聊是否可显示，按成员加密能力完整性判断；不满足条件则不显示。

## 前端结构建议
### 现状判断
`web/src/views/ChatView.vue` 已经承载过多职责：
- 消息中心布局
- AI 助手入口
- 收藏入口
- 好友/群聊列表
- E2EE 密钥初始化
- 好友加密发送/解密
- 群加密发送/解密
- websocket 消息处理
- 多选收藏逻辑

继续在单文件内叠加普通聊天与加密聊天双链路，维护成本会显著上升。

### 建议拆分
#### 1. `ChatView.vue` 转为普通消息中心容器
负责：
- 消息中心布局
- AI 助手入口
- 收藏入口
- 加密通道入口
- 普通好友/群聊会话加载
- 普通消息发送/接收

不再负责：
- 私钥初始化
- 公钥上传
- 加密消息加解密
- “对方未启用端到端加密消息”类提示

#### 2. 新增 `EncryptedChatView.vue`
负责：
- 加密页深色专业风格
- 只展示可加密对象
- 现有 E2EE 好友消息逻辑
- 现有 E2EE 群消息逻辑
- 现有加密 websocket 消息处理
- 当前设备私钥 / 公钥能力校验

#### 3. 抽取共享展示组件（仅展示层）
可抽取：
- 会话列表项
- 聊天消息列表
- 消息气泡
- 输入区骨架
- 移动端列表/会话切换骨架

不建议抽成“一个统一业务大组件”，避免普通与加密业务逻辑重新耦合。

## 后端结构建议
### 普通聊天新增模块
建议增加与现有加密链路平行的普通聊天模块：
- 普通好友消息 model / repository / service / handler
- 普通群消息 model / repository / service / handler
- 对应 router 注册与 router tests

### 加密聊天保持原状
现有加密消息模块尽量不改协议语义，仅为新页面复用。

### websocket
如果当前 websocket 事件只覆盖现有加密消息，需要补充普通聊天事件类型，确保：
- `/chat` 收到普通好友/群聊实时消息。
- `/encrypted-chat` 收到现有加密好友/群加密实时消息。
- 两页按各自会话类型消费各自事件，不互串。

## UI / 视觉设计
### 普通页 `/chat`
风格定位：轻量、日常、社交。
- 延续当前 Apple 风格主基调。
- 保留浅色背景与清爽卡片。
- 加密通道作为醒目入口卡片出现。
- 输入区文案使用普通聊天语义，如“输入消息，按回车发送”。
- 不再展示“加密通道已开启”主状态块。

### 加密页 `/encrypted-chat`
风格定位：高级、专业、沉稳、克制的黑客帝国风格。
- 整体使用黑 / 深灰 / 冷绿深色体系。
- 点缀使用低饱和荧光绿、青色。
- 面板采用深色半透明卡片、细描边、微弱发光。
- 文案语义偏专业：
  - `Encrypted Channel`
  - `Secure Session`
  - `End-to-End Protected`
- 去掉 AI、收藏等杂项入口，保持纯聊天。

## 错误处理
### 普通页
只展示普通聊天语义错误：
- 消息发送失败
- 会话加载失败
- 连接已断开，请重试

禁止出现：
- 对方未启用端到端加密消息
- 当前环境不支持端到端加密
- 当前账号公钥不可用

### 加密页
保留安全语义错误，但文案统一专业化：
- 当前设备私钥不可用
- 对方未开启加密能力
- 该群存在未具备加密能力的成员
- 当前环境不支持安全会话

## 移动端要求
- 普通页与加密页都保留当前“列表 / 会话切换”体验。
- 加密页虽然深色化，但移动端层级与返回交互保持与普通页接近，降低学习成本。

## 测试策略
1. 先为普通好友/群聊天接口补路由测试。
2. 为普通聊天与加密聊天事件分流补充后端测试。
3. 前端验证：
   - `/chat` 正常显示 AI、收藏、加密入口。
   - `/chat` 点击好友/群聊走普通聊天。
   - `/encrypted-chat` 只显示可加密对象。
   - `/encrypted-chat` 能查看和发送现有加密历史。
4. 跑前端 `npm run build`。
5. 跑后端相关 `go test`。

## 验收标准
1. `/chat` 中可见 AI 助手、我的收藏、加密通道入口。
2. `/chat` 中点击好友/群聊进入普通聊天，而不是加密聊天。
3. `/chat` 页面不再展示加密主状态语义。
4. `/encrypted-chat` 为独立页面，只保留聊天功能。
5. `/encrypted-chat` 左侧仅显示具备加密能力的好友/群聊。
6. 现有加密聊天历史在 `/encrypted-chat` 中可正常查看。
7. 普通聊天历史与加密聊天历史彼此分离。
8. AI 助手与我的收藏不出现在 `/encrypted-chat`。
9. 普通页和加密页在移动端都保留基础列表/会话切换体验。
10. 加密页整体视觉明显区别于普通页，达到深色、专业、沉稳目标。
